# Дизайн-документ проєкту: Консольна текстова гра та система управління станами

## 1. Загальний огляд системи
Проєкт являє собою модульну об'єктно-орієнтовану систему для запуску текстової рольової гри з підтримкою управління персонажами, бойової системи та збереження прогресу. Архітектура побудована за тришаровою моделлю: шар представлення, шар бізнес-логіки та шар постійності даних.

## 2. Архітектура проєкту
Система розділена на три незалежні рівні:
1. Шар представлення відповідає за взаємодію з користувачем. Поточна реалізація представлена консольною оболонкою CLI, спроєктованою так, щоб у майбутньому без змін у бізнес-логіці додати графічний інтерфейс.
2. Шар бізнес-логіки містить моделі персонажів, правила бою, ігровий цикл та механізми створення знімків стану гри.
3. Шар постійності забезпечує збереження та завантаження стану гри у форматі JSON.

## 3. Детальний опис реалізації командного інтерфейсу
Командний інтерфейс реалізовано як окремий пакет `cli` з чітким розмежуванням відповідальності:

### 3.1. Фасад CLI
Клас `CLI` виступає єдиною точкою входу для зовнішнього коду та інкапсулює роботу парсера, стратегій команд і рендерерів:
* `use_strategy` реєструє конкретну групу команд у системі.
* `exec_command` передає сирий рядок користувача до парсера аргументів, знаходить відповідну стратегію за назвою команди та запускає її виконання.
* `display` приймає об'єкт, що реалізує інтерфейс `IRenderable`, та виводить його текстове представлення у консоль.

### 3.2. Парсинг аргументів
Клас `ArgParser` розбирає вхідний рядок на назву команди, позиційні аргументи та іменовані параметри у форматі ключів, повертаючи типізований об'єкт `Args`.

### 3.3. Стратегії команд
Для уникнення монолітного обробника використано патерн Стратегія через інтерфейс `ICommandStrategy`. Команди поділено на три категорії:
* `InfoCommandStrategy` відповідає за вивід списку доступних персонажів, їхніх характеристик та поточного стану гри.
* `GameplayCommandStrategy` реалізує трансформативні дії під час ігрового циклу, зокрема вибір героя, старт гри, атаку ворога та використання лікування.
* `InfrastructureCommandStrategy` виконує системні операції, такі як збереження прогресу у файл, завантаження збереження та завершення роботи.

### 3.4. Відображення даних
Використано інверсію залежностей через інтерфейси `IRenderable` та `IRenderer`. Моделі ядра гри реалізують `IRenderable`, делегуючи форматування конкретним консольним рендерерам `CharacterRenderer` та `GameStateRenderer`. Допоміжний клас `CLIGraphic` формує рамки, таблиці та смужки здоров'я.

## 4. Сценарій роботи користувача
1. Користувач переглядає доступних персонажів командою `heroes`.
2. Обирає героя командою `select` із вказанням номера або імені.
3. Запускає ігровий процес командою `start`.
4. Виконує ігрові дії `attack`, `heal`, `status` у межах основного циклу.
5. Зберігає результат командою `save` або завантажує попередню сесію командою `load`.
